# cs2wd-40

> 完美世界竞技平台 / CS2（及其他游戏）的 **CPU 与内存占用优化器**。
> 让平台后台进程不再抢游戏 CPU，并在游戏前自动清理吃内存的后台应用。

![版本](https://img.shields.io/badge/version-5.2-blue) ![平台](https://img.shields.io/badge/platform-Windows%2010%2F11-lightgrey) ![体积](https://img.shields.io/badge/exe-157%20KB-green)

---

## ✨ 这是什么

一个 **157 KB 的单文件 Windows 桌面应用**，无安装、无黑框、无第三方依赖（系统自带 .NET 4.8 即可运行）。

它做三件事：

1. **CPU 隔离** —— 把完美世界平台的所有进程锁死在 CPU0-CPU1 并降为低优先级；让游戏独占剩余核心并以较高优先级运行。
2. **内存清理** —— 游戏启动瞬间自动关闭你勾选的后台应用（浏览器 / QQ / 网盘 / Office 等），并在界面上标注每个进程「安全 / 慎用 / 禁止」。
3. **赛后报告** —— 游戏结束后自动通读日志，弹窗告诉你本局有没有设置失败；一切正常则自动清理日志，不留垃圾文件。

## 🧠 工作原理

现代 Windows 的游戏体验卡顿，很大一部分原因是**游戏平台的后台进程**和**游戏本体**在抢 CPU 核心。
┌─────────────────────────────────────────────────────┐
│  16 核 CPU（之前）                                    │
│  ├── 平台进程 A  ──┤                                 │
│  ├── 平台进程 B  ──┤   ← 到处乱窜，占满所有核心       │
│  ├── cs2.exe     ──┤                                 │
│  └── 系统/Driver ──┤                                 │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  16 核 CPU（优化后）                                  │
│  ├── CPU0-CPU1   → 平台进程（效率模式 + 低优先级）    │
│  └── CPU2-CPU15  → cs2.exe（独占 + 高优先级）        │
└─────────────────────────────────────────────────────┘
效果：平台更新/下载/上报都在后台低功耗运行，游戏独占物理核心，帧率和稳定性显著提升。

## 🚀 快速开始

### 系统要求
- Windows 10 2004 及以上，或 Windows 11
- .NET Framework 4.8（Win10 1903+ 系统自带）
- 管理员权限（exe 已内置 manifest，双击会自动提权，无需手动右键）

### 三步上手

1. **下载** —— 在本仓库页面点绿色 `Code` → `Download ZIP`，或直接下载 `cs2wd-40.exe`
2. **双击 `cs2wd-40.exe`** —— 弹出 UAC 点「是」
3. **点「⚙ 配置」** —— 点「自动探测」找到完美世界竞技平台路径，或手动「浏览」选择；需要的话在「② 后台应用管理」勾选要在游戏时关闭的软件
4. 点「保存并应用」→ 点「▶ 启动」

**2. 双击 `PW-CS2-Optimizer.cmd`** — 自动弹 UAC 提权，首次运行会打开配置向导

**3. 在配置向导里填好：**
   - 平台 exe 路径（可以点「自动探测」一键找到）
   - 游戏进程名（默认 `cs2`）
   - 其他参数保持默认就行

   点「保存并启动」，脚本会自动打开完美世界平台并开始监控。

## ⚙️ 配置说明

| 文件 | 说明 |
|------|------|
| `PW-CS2-Optimizer.cmd` | **双击入口**，自动提权 + 单实例检查 + 配置向导触发 |
| `PW-CS2-Optimizer.ps1` | **核心脚本**，约 950 行，包含全部监控逻辑和 P/Invoke 封装 |
| `PW-CS2-Optimizer-UI.ps1` | **配置向导**，WinForms 图形界面，零外部依赖 |
| `.gitignore` | 排除日志/配置/IDE 文件 |

| 配置项 | 默认 | 说明 |
|--------|------|------|
| 平台 exe 路径 | 必填 | 完美世界竞技平台主程序 |
| 游戏进程名 | `cs2` | 不带 .exe，改名称即可支持 DOTA2 / Valorant 等 |
| CPU 相关性 | 排除 CPU0/1 | `排除 CPU0/1` / `全部核心` / `自定义掩码` |
| 自定义掩码 | 空 | 十六进制，如 `FFFC` 表示 CPU2-CPU15 |
| 游戏优先级 | AboveNormal | AboveNormal / High / Normal |
| 平台占用核数 | 2 | 平台锁在 CPU0 ~ CPU(N-1)，游戏获得剩余核心 |
| 巡检间隔 | 1000 ms | 游戏中最少 1000 ms 一次 |
| 自动打开平台 | 开 | 点击启动时若平台未运行则自动拉起 |
| 日志上限 | 10 MB | 超过自动归档为 `.log.bak` |
| 游戏结束后清理日志 | 开 | 报告后删除本局日志 |
| 游戏时关闭应用 | 空 | 在「② 后台应用管理」勾选 |

### 默认的进程策略

| 进程 | CPU 相关性 | 优先级 | 效率模式 | 内存优先级 |
|------|-----------|--------|----------|-----------|
| 完美世界平台（全部子进程） | CPU0-CPU1 | BelowNormal | 开启 | Low |
| 游戏（默认 cs2） | CPU2-CPU15 | AboveNormal | 关闭 | 正常 |

## 🧠 为什么有效

配置文件位置（首次保存后生成）：`<脚本目录>\PW-CS2-Optimizer.config.json`

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `PlatformPath` | （必填） | 完美世界竞技平台 exe 完整路径 |
| `GameProcessName` | `cs2` | 游戏进程名（不带 .exe），改了就能支持别的游戏 |
| `Cs2Affinity` | `Exclude01` | `Exclude01` / `All` / `Custom`（自定义掩码） |
| `CustomMask` | 空 | 十六进制 CPU 掩码，如 `FFFC` = 只用 CPU2-15 |
| `Cs2Priority` | `AboveNormal` | `High` / `AboveNormal` / `Normal` |
| `PlatCoresCount` | `2` | 平台占用核心数（1-4），游戏自动获得剩余核心 |
| `IntervalMs` | `2000` | 巡检间隔 ms（游戏中自动缩到 1000ms） |
| `AutoLaunchPlatform` | `true` | 启动优化器时是否自动打开平台 |
| `LogMaxMb` | `10` | 日志文件最大 MB，超过自动归档 |
| `PlatNamesExtra` | `[]` | 额外需要识别为平台的进程名 |

### 命令行覆盖

```powershell**
# 测试全核方案
PW-CS2-Optimizer.ps1 -Cs2Affinity All

# 换个游戏试试
PW-CS2-Optimizer.ps1 -GameProcessName dota2

# 诊断进程识别（不运行监控）
PW-CS2-Optimizer.ps1 -Dump

# 打开配置向导
PW-CS2-Optimizer.ps1 -ShowConfig

## 🔐 安全说明

**Q: 为什么提示"不是管理员权限"？**  
A: 修改进程亲和性需要管理员权限。双击 `.cmd` 会自动弹 UAC 提权。

**Q: 反作弊进程设置失败（错误码 5）？**  
A: 正常。反作弊/内核驱动进程权限比脚本高，任何工具都改不动。

**Q: 小核机器会怎么样？**  
A: 4 核以下自动把平台核数降到 1，游戏独占 3 核。2 核机器也能跑只是效果打折。

**Q: Windows 7/8 能用吗？**  
A: 可以跑但**效率模式(EcoQoS)不可用**（Win10 2004 才引入）。相关性和优先级设置仍然有效。

**Q: 怎么退出？**  
A: 关闭脚本控制台窗口，或者平台和游戏都退出后 8 秒自动停止。

**Q: 日志文件在哪？**  
A: 桌面 `PW-CS2-Optimizer.log`，里面每 30 秒一行 CPU/内存采样。
